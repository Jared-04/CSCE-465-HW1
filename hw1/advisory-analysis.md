The advisory I chose to analyze was a critical vulnerability in OverClaw versions before 2026.6.9 [OpenClaw advisory page](https://github.com/openclaw/openclaw/security/advisories/GHSA-mm9g-83wh-mhwj) that allowed for attackers to escalate their privileges using the agent. This high risk vulnerability affected the execution scheduler system, known as the isolated cron job subsystem. Attackers were able to target this subsystem as users with limited privileges to escalate their permissions, allowing them to potentially access tools that were strictly denied in their main session such as shell access and terminal commands. 
The vulnerable system is the isolated cron job handler responsible. This handler is a feature of OverClaw that allows for the automated execution of background tasks, known as cron jobs. In order for an attacker to escalate their privileges, a number of preconditions must be met. The cron job handler must already be active (or at least turned on), and the gateway the system runs on must have a variety of users with different permission levels (specifically, one with admin privileges). If an attacker is able to access these cron jobs or the scheduler via the shared gateway, then they can execute commands with elevated privileges. 
The issue stems with how the cron job handler manages permissions for the background processes. When a task is scheduled to run, it gets registered by the handler with the user that issued it, the scheduled time, metadata, and a tool restriction list placed on the user. This gets stored to be spun back up at the scheduled time. If the user is disconnected at the time of the execution, an isolated background thread is created to run this task. However, the handler fails to properly include the tool restrictions imposed on the user who created the task. Now when the task is executed, the proper restrictions are not included and the task runs with default (usually elevated) privileges. 
	The impact of this vulnerability is quite severe. An attacker with access to the cron job scheduler gains unrestricted access to actions that could potentially be harmful to the system. By leveraging this privilege escalation, the attacker can open gateways to further exploit the system and gain unauthorized access to sensitive information. In order to prevent this, the 2026.6.9 patch ensures that restrictions applied to a user are bound to cron jobs scheduled by them. This means that a low-privilege attacker can only schedule tasks that have the same restrictions as them. As a regression test, we have a user with restricted access schedule a cron job. We then check that unauthorized tools are blocked during the execution of the scheduled task. 
	This vulnerability does not require prompt injection. We assume that the attacker has low-level access to the agent and simply abuses a bug in the permission check to execute scheduled tasks with elevated privileges. An attacker could, however, leverage prompt injection against a user with low-level privileges by chaining it with a different attack. This is done by telling the agent to utilize the cron job scheduler tool to create a scheduled task that runs an unauthorized command that would typically be restricted by the user permissions. Restrictions imposed on the user would be completely ignored, and the unauthorized command would run unchecked.
